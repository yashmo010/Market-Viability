Source of truth used for this section: the supplied 21-page research paper. Page numbers below refer to that PDF.
R-01 — P0 — Research
Location: p.13, Fig. 6
Issue: The plotted holdout statistic is ρ=0.437 with AUC=0.826 and CI [0.28,0.58], while the surrounding text, Table 2, abstract,
and conclusion use ρ=0.529 and AUC=0.903.
Why it matters: This is not a cosmetic difference. A reviewer cannot know which result is the actual experiment.
Required correction: Freeze the holdout prediction file and regenerate the scatter plot from the exact same 118 predictions used
for the reported statistics. Then update abstract, Table 2, text, caption, and conclusion from that single result object.
Verification / evidence needed: Also verify whether the figure was generated from an earlier model version. Do not manually edit the annotation;
regenerate it.
R-02 — P0 — Research
Location: p.1 vs p.12
Issue: The abstract gives 95% CI [0.31,0.61], while the validation section gives bootstrap 95% CI [0.377,0.654].
Why it matters: Conflicting uncertainty intervals are a direct reproducibility problem.
Required correction: Use one exact bootstrap procedure and report its exact interval everywhere.
Verification / evidence needed: Store the random seed, bootstrap method, resampling unit, number of resamples, and statistic used.
R-03 — P0 — Research
Location: p.9–10, Fig. 1 and Fig. 3
Issue: The chart artwork states n=732 even though the final cleaned dataset is 631 products and the captions/table text state
n=631.
Why it matters: This creates an immediate credibility problem and suggests figures came from an earlier experiment.
Required correction: Regenerate all model-comparison figures from the final 631-row analysis dataset.
Verification / evidence needed: Search every figure/table caption and embedded image for 640, 631, 732, 118, 125, 505, 513 and reconcile each number.
R-04 — P0 — Research
Location: p.10, Fig. 3
Issue: The “BEST/Good/Weak” verdict implies an overall ranking, but Gradient Boosting has higher accuracy, precision, recall,
specificity, F1 and ties AUC; XGBoost leads the primary regression metrics and ties AUC.
Why it matters: The current verdict is not a neutral statistical summary and is not supported by a predeclared decision rule.
Required correction: Remove the verdict column. State a predeclared selection rule such as: R² is the primary regression metric,
RMSE secondary, AUC an auxiliary extreme-quintile diagnostic, runtime tertiary.
Verification / evidence needed: If you want a model-selection score, define it before evaluation and report how it is calculated.
R-05 — P0 — Research
Location: p.7, p.10–14
Issue: The paper says category priors are training-only in the random holdout, but the bridging prompt uses price quartiles, mean
aspect scores, pain points and strengths. It is not explicit that every one of these profile elements is computed only from training
data for every holdout.
Why it matters: Any post-launch or test-product information entering the category profile would violate the launch-blind claim.
Required correction: Add a “feature provenance and leakage guard” table listing every serving input, its source, timestamp, and
whether it is computed from training-only data.
Verification / evidence needed: For both holdouts, verify category statistics, pain points, strengths, calibration reference distributions, and trust weights are
frozen before test predictions.

R-08 — P0 — Research
Location: p.6, p.12
Issue: The success label is min–max normalized within category. The paper does not explicitly state whether category min/max
parameters for evaluation targets and training labels are fitted only on the training split.
Why it matters: For pooled holdout Spearman, using test-set extrema to normalize the target can leak test distribution information
and can change between-category ordering.
Required correction: Fit label-scaling parameters on training data only for each evaluation split; apply them to the test outcomes.
For within-category Spearman/AUC, the issue is less consequential, but pooled metrics must use a clean protocol.
Verification / evidence needed: Recompute pooled metrics under the training-only scaling rule and compare with current results.

R-10 — P0 — Research

model performance, and score distributions. If the difference is material, use the rating-blinded extraction for the headline model.
Verification / evidence needed: Add a human/automatic check for rating leakage into aspect outputs.

version of the system.

Why it matters: This is the central methodological mismatch between the papers.
Required correction: Rewrite the proposed methodology around the two-stage learning/bridging pipeline.
Verification / evidence needed: The survey's architecture figure, abstract, gap, results and conclusion must all use the same story.

7. Correct scientific narrative for both papers
The two papers should use the following exact conceptual chain. This is the cleanest version of your contribution:
Historical consumer evidence → 43,000+ reviews → null-forcing LLM ABSA → nine consumer aspects → XGBoost
learns aspect-profile/viability relationship → trained viability model.
New product at launch → price + launch-available specifications + other verified pre-launch metadata →
category-grounded specification-to-aspect bridge → estimated nine-aspect profile → trained XGBoost →
viability/rank estimate → SHAP explanations + measured confidence + abstention.
This distinction fixes the leakage concern that appeared in the earlier survey version: the new product's review count, rating and
review velocity are not used as predictive inputs at inference time. They are part of the historical outcome used to teach the model
what “viability” means.

market attention. The validated claim is a survivor-product, within-category viability ranking from launch-available
specifications, with strong variation by category.
